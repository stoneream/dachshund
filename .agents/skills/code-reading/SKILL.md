# コードリーディング

既存コードを調査し、「どこから入り、何を経由し、どこへ作用するか」を根拠付きで説明する。

## 適用範囲

- プロジェクトやサブシステムの構造把握
- 機能、リクエスト、ジョブ、イベントの処理経路の追跡
- 変更候補に対する参照元、参照先、設定、テストの調査
- 不具合調査に必要な現況理解

コード品質の網羅的な評価、脆弱性分析、修正案の採点へ自動的に広げない。

## 参照

対象範囲を決めた後、調査を始める前に[コード読解チェックリスト](references/reading-checklist.md)を読む。出力前に、対象に関係する観点を見落としていないか再確認する。該当しない項目を確認結果として列挙しない。

## 進め方

1. ユーザーが知りたい対象と、必要な深さを明確にする。
2. リポジトリの指示、README、ビルド設定、主要ディレクトリを確認する。
3. エントリーポイントと公開インターフェースを特定する。
4. 呼び出し、データ変換、状態変更、外部I/Oを順に追跡する。
5. 設定、依存注入、生成コード、動的参照など、検索のみでは見落としやすい接続を確認する。
6. テストと必要な履歴を読み、期待動作と設計意図を補強する。
7. 読み取れた事実、推論、未確認事項を分けて整理する。

最初から全ファイルを精読しない。全体像を作ってから、質問に関係する経路を深く読む。

## 調査観点

### 目的と構成

- システムや対象機能の目的、利用者、主要なユースケース
- 言語、フレームワーク、ビルド方式、主要な外部依存
- ディレクトリ、モジュール、レイヤーの責務と境界
- エントリーポイント、公開インターフェース、設定の読み込み経路

### 処理とデータ

- 典型的な処理に加え、分岐、異常系、終了条件まで含む制御フロー
- 入力検証、型や形式の変換、状態変更、永続化、キャッシュを含むデータフロー
- トランザクション、非同期処理、イベント、ジョブ、再試行の接続関係
- データベース、ファイル、ネットワーク、外部APIなどとのI/O

### 仕様と設計意図

- 型、公開API、スキーマ、テストから読み取れる契約と期待動作
- README、設計文書、コメント、TODO、FIXMEに記録された意図や制約
- ログやトレースから確認できる実行時の経路
- 履歴から確認できる導入理由、互換性要件、過去の不具合

文書やコメントと実装が異なる場合は、どちらかへ推測で合わせず差異を示す。

### 影響範囲

- 変更候補を呼び出す側と、変更候補が呼び出す側
- 共有される型、データ、設定、キャッシュ、イベント、永続形式
- テスト、生成処理、移行処理、デプロイ、監視、運用文書
- 外部利用者や別リポジトリなど、ローカル検索では確定できない依存

## 根拠の扱い

- 重要な説明にはファイルと該当箇所を示す。
- コメントや文書のみで断定せず、実装やテストと突き合わせる。
- 名前や一般的な慣習から推測した内容は、推論であることを明記する。
- 実行時にしか確定しない挙動は、静的調査の限界を明記する。
- 調査中に問題らしき箇所を見つけても、依頼が読解のみの場合は補足として分離する。

## 出力

必要な項目を次の順で返す。

1. 質問への結論
2. 主要な処理経路または構造
3. 結論を支えるコード上の根拠
4. 影響範囲
5. 未確認事項や追加調査が必要な点
