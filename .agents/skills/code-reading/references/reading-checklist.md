# コード読解チェックリスト

対象の質問に関係する節を使用する。確認した項目の一覧ではなく、質問への回答に必要な事実、推論、未確認事項を整理する。

## 目的と利用者

- システムまたは機能が解決する問題と、主な利用者を確認する。
- 代表的なユースケースと、処理が完了したと判断する状態を確認する。
- README、仕様書、チケットなどに記載された目的と、実装が提供する挙動を区別する。
- 対象外の機能や互換性要件が明記されている場合は記録する。

## 技術と構成

- 言語、フレームワーク、ランタイム、ビルドツール、パッケージ管理方式を確認する。
- 主要ディレクトリ、モジュール、レイヤー、サービスの責務を確認する。
- エントリーポイント、公開API、CLI、ルート、ジョブ、イベント購読を特定する。
- 設定の定義元、既定値、環境別上書き、依存注入、プラグイン登録を追跡する。
- 生成コード、規約による自動登録、リフレクション、文字列参照を確認する。

## 制御フロー

- 入口から主要処理、出力、副作用までを順に追跡する。
- 条件分岐、早期終了、例外、キャンセル、タイムアウトを確認する。
- 同期処理と非同期処理の境界、イベント発行後の処理、バックグラウンド実行を確認する。
- 再試行、再実行、重複実行に対する制御を確認する。
- 複数の入口が同じ処理へ合流する場合は、入口ごとの差を確認する。

## データと状態

- 入力の型、検証、正規化、変換、既定値を確認する。
- 状態を保持する場所と、状態遷移を発生させる処理を確認する。
- 永続化、トランザクション、キャッシュ、キュー、外部APIへの書き込みを追跡する。
- データの正本と派生物、同期方法、無効化条件を確認する。
- 時刻、順序、識別子、バージョンが処理判断へ与える影響を確認する。

## 異常系と実行時情報

- 失敗がどこで生成され、変換され、記録され、利用者へ返るかを追跡する。
- 部分成功、復旧、補償処理、リソース解放を確認する。
- ログ、メトリクス、トレースが示す実際の経路と、静的に読んだ経路を照合する。
- 実行環境、権限、外部サービスによって変わる挙動を分離する。

## 仕様と設計意図の根拠

- 型、テスト、公開インターフェースから期待される契約を読み取る。
- コメント、TODO、FIXMEは手掛かりとして扱い、実装や履歴で裏付ける。
- 単体、統合、E2Eテストがそれぞれ示す正常系、境界値、異常系を確認する。
- 変更履歴から導入理由、過去の不具合、互換性判断を確認する。
- 文書と実装が一致しない場合は、差異と確認できた時点を示す。

## 影響範囲

- 対象を呼び出す側、対象が呼び出す側、共有データを利用する側を確認する。
- 公開API、型、設定、保存形式、イベント、キャッシュの利用者を確認する。
- テスト、生成処理、移行、デプロイ、監視、文書への影響を確認する。
- 別リポジトリ、外部利用者、運用手順など、ローカル検索で確定できない依存を分離する。

## 調査完了確認

- 質問への直接的な回答と、回答を支えるコード上の経路が対応している。
- 事実、推論、実行確認が必要な事項を区別している。
- 主要な入口、状態変更、外部I/O、異常系を見落としていない。
- 読解依頼を品質評価や修正提案へ無断で広げていない。
