# 不要コード削除チェックリスト

削除候補の種類に関係する項目を使用する。静的検索の結果だけで不使用を断定せず、実行時接続、外部契約、移行状態を確認する。

## 候補の成立

- import、変数、関数、型、モジュールに静的参照がない。
- 実装が登録、構築、読み込み、呼び出しされる入口がない。
- 条件分岐へ到達する入力や状態が存在しない。
- 機能フラグ、互換処理、旧スキーマの終了条件が満たされている。
- 同等の処理へ置き換えられ、旧経路へ戻る条件が残っていない。
- 空実装が拡張点、既定動作、契約上のプレースホルダーとして使われていない。

## 動的な参照

- リフレクション、文字列名、設定値、ルーティングから参照されていない。
- DIコンテナ、サービスローダー、プラグイン、フレームワーク規約で登録されていない。
- シリアライズ、デシリアライズ、テンプレート、マイグレーションから名前を参照されていない。
- ネイティブ連携、FFI、マクロ、生成コードから使用されていない。
- テスト、開発ツール、ビルド、パッケージング時だけ使用される対象ではない。

## 外部契約

- 公開API、CLI、設定キー、環境変数、イベント、ファイル形式として公開されていない。
- 別リポジトリ、利用者コード、運用スクリプトから参照されていない。
- 後方互換性、非推奨期間、サポート契約が残っていない。
- データ復旧、ロールバック、旧バージョン混在のために必要な処理ではない。
- 文書や例に記載がある場合、その記載が単に古いのか利用契約なのかを確認している。

## 履歴と運用証拠

- 導入理由と、現在も残す必要がある条件を履歴から確認する。
- 未使用と判断する期間や利用頻度に十分なログ、メトリクス、カバレッジがある。
- 季節処理、障害時処理、管理者操作など、低頻度の入口を見落としていない。
- 観測できない利用経路を、不使用の証拠として扱っていない。

## 関連対象

- 対象専用のテスト、フィクスチャ、モック、スナップショットを確認する。
- 対象専用の設定、機能フラグ、環境変数、権限を確認する。
- 対象専用の依存パッケージ、ビルドプラグイン、生成処理を確認する。
- README、API文書、運用手順、図、コメントを確認する。
- 監視、アラート、ダッシュボード、デプロイ設定を確認する。

## 削除単位

- 独立して検証できる最小単位へ分ける。
- 挙動変更、リファクタリング、整形を同じ差分へ混在させない。
- 共有コードや公開契約を、対象専用と誤認して削除しない。
- 依存関係を削除する場合は、ロックファイルと生成物の正規の更新手順を使用する。
- 移行中の対象は、削除ではなく終了条件の明確化を優先する。

## 検証

- 削除した名前、設定、リソースへの参照が残っていない。
- ビルド、型検査、lint、対象テストが成功する。
- 動的登録、起動、代表的な実行経路が維持されている。
- 公開API、保存データ、移行、ロールバックへ影響がない。
- 削除前から存在した失敗と、新しく発生した失敗を区別している。
- 検証できない外部利用や低頻度経路を残る不確実性として報告している。
