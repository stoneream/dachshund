# 不要コードの安全な削除

削除対象が到達不能または不要であることを確認し、最小単位で削除して挙動が維持されることを検証する。

## 適用範囲

- 参照されない関数、型、モジュール、設定
- 廃止済み機能のコード、フラグ、互換処理
- 使用されないリソース、依存パッケージ、ビルド設定
- 到達不能な分岐や終了後の処理

一度しか使われない変数、コード重複、長い関数は、その条件のみではデッドコードではない。

## 参照

削除候補を定義した後、参照調査を始める前に[不要コード削除チェックリスト](references/removal-checklist.md)を読む。削除前と検証後に該当項目を再確認する。不使用を証明できない項目は削除せず、不確実性として扱う。

## 候補の分類

### 未使用

- 参照されないimport、変数、関数、型、モジュール
- 登録されない実装、構築されないオブジェクト、読み込まれない設定
- 利用されない依存パッケージ、リソース、ビルド入力

### 到達不能

- 常に成立しない条件分岐
- 終了、return、throwの後に残る処理
- 現行の入口や状態遷移から到達できない経路

### 空実装と重複

- 契約上の目的を失った空の関数や仮実装
- 同等の実装へ完全に置き換えられた旧経路
- 生成物や派生物として重複し、正規の入力として使用されない対象

空実装や重複は、拡張点、互換性、可読性などの役割が残っていないことを確認してから候補にする。

### 廃止済み

- 終了条件を満たした機能フラグと旧実装
- 移行が完了した互換処理、旧スキーマ、旧API
- サポート対象から外れ、利用者が残っていない非推奨機能

## 調査

1. 削除候補の定義と、想定される入口を特定する。
2. 静的参照を検索し、呼び出し元、import、設定、テスト、文書を確認する。
3. リフレクション、文字列参照、DI、プラグイン登録、ルーティング、シリアライズ、生成コードからの利用を確認する。
4. 公開API、外部利用、移行期間、機能フラグ、後方互換性の対象でないか確認する。
5. 必要に応じて履歴を読み、残されている理由や廃止条件を確認する。
6. 静的証拠のみで確定できない場合は、テスト、ログ、カバレッジ、実行確認で補強する。

未使用であることを確認できない場合は削除せず、不確実な参照経路を報告する。

## 削除

- 独立して検証できる最小単位で削除する。
- 対象専用として存在した設定、テスト、文書、依存関係も追跡する。
- 共有コードや公開インターフェースまで不用意に巻き込まない。
- 削除と無関係な整形やリファクタリングを混在させない。
- 非推奨APIは、利用者や移行条件が残っている間は単なるデッドコードとして扱わない。

## 検証

対象に応じて、参照検索、ビルド、型検査、lint、単体テスト、統合テスト、実行確認を行う。削除前から失敗していた検証は区別し、削除による新しい失敗がないことを確認する。

## 出力

- 削除した対象
- 未使用と判断した根拠
- 併せて更新した設定、テスト、文書、依存関係
- 実行した検証と結果
- 残した候補と、その不確実性
