# コードレビュー

指定されたコードや差分から、利用者や運用へ影響する問題を根拠付きで発見する。

## 境界

- レビュー対象、比較元、期待される挙動を最初に確認する。
- 問題発見が主目的であり、ユーザーが修正も求めていない限りファイルを変更しない。
- PR・MR全体の履歴やCIを含むレビューは `pull-request-review` の範囲とする。
- 一般論のチェックリストを機械的に当てはめず、対象コードで成立する問題を優先する。

## 参照

レビュー対象と期待動作を特定した後、レビューを始める前に[コードレビューチェックリスト](references/review-checklist.md)を読む。出力前に、対象に関係する観点を見落としていないか再確認する。対象コードで成立しない項目は指摘として挙げない。

## 進め方

1. リポジトリの指示と、対象に関係する仕様、テスト、周辺実装を確認する。
2. 差分がある場合は変更意図と変更前後の挙動を把握する。
3. 変更された公開API、型、設定、データ形式の呼び出し元と利用先を追跡する。
4. 正常系に加えて、失敗時、境界値、並行実行、再実行時の挙動を確認する。
5. 既存テストが問題を検出できるか、必要な検証が欠けていないかを確認する。
6. 各指摘について、成立条件、影響、コード上の根拠を確認する。
7. 重要度順に指摘を返す。

## 確認観点

対象に関係する観点に絞って使用する。

### 挙動とデータ

- 仕様、ビジネスルール、既存契約に反する挙動
- null、空値、境界値、上限値、不正値に対する処理
- 型、時刻、文字コード、単位、形式の変換に伴う情報損失
- データ消失、不整合、重複処理、誤った状態遷移
- トランザクション境界、部分成功、再実行、冪等性

### 失敗時と運用

- エラーの握りつぶし、誤分類、利用者に誤解を与えるメッセージ
- タイムアウト、再試行、キャンセル、フォールバックの相互作用
- ファイル、接続、ロック、プロセスなどの解放漏れ
- 障害や重要な状態変化を追跡するために必要なログ、メトリクス、相関情報
- ログに含まれる秘密情報や個人情報、過剰なログ量

### インターフェースと互換性

- API、型、イベント、設定、デフォルト値、永続形式の変更
- 呼び出し元、利用先、生成物、移行処理との互換性
- 省略時の挙動、バージョン差、段階的な導入時の旧新混在

### 並行処理、性能、リソース

- 競合、順序依存、非原子的な更新、非同期処理の取りこぼし
- 無制限な読み込みや並列実行、N+1、不要な外部I/O
- 実際の入力規模や呼び出し頻度で問題になる計算量、メモリ、接続数

### セキュリティ境界

- 信頼できない入力の検証と出力時のエスケープ
- 認証、認可、所有権、テナント境界の確認漏れ
- 秘密情報、個人情報、機微なデータの保存、転送、露出
- 依存関係や危険な機能の導入による攻撃面の拡大

専門的な脆弱性分析が必要な場合は、対象に応じた脆弱性分析スキルの範囲とする。

### 保守性

- 変更理由と一致しない責務の混在、重複、過剰な抽象化
- 暗黙の前提、強い結合、変更時に同期が必要な複数箇所
- プロジェクトの規約や周辺実装から外れ、誤変更を誘発する構造

### テスト

- 正常系、境界値、異常系、回帰条件を検出できるテスト
- assertionが対象の結果を実際に観測しているか
- モックと実環境の差、時刻、順序、並行性に依存する不安定さ
- 公開契約やデータ移行など、変更の安全性を確認する検証の欠落

個人的な好みに基づくスタイル指摘や、プロジェクトで採用されていない一般原則の強制は避ける。

## 重要度

### 重大

障害、データ損失、セキュリティ侵害、主要機能の明確な回帰につながる。

### 要対応

現実的な条件で誤動作する、または変更の安全性を確認できない。

### 改善

直ちに誤動作しないが、具体的な保守・運用上の負担を生む。

## 出力

指摘を先に示し、各指摘には次を含める。

- 重要度
- 対象ファイルと該当箇所
- 問題が成立する条件
- 想定される影響
- 根拠と最小限の修正方向

指摘がない場合はその旨を明記し、実施できなかった検証や残る不確実性を短く添える。変更要約は必要な場合に限り最後に置く。
