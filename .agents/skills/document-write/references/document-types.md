# 文書種別ガイド

作成または更新する文書種別の節を使用する。複数種別の責務を一つの文書へ混在させる場合は、主目的を決め、詳細を別文書へ分離する。

## README

### 含める内容

- プロジェクトまたはコンポーネントの目的
- 主な利用者と代表的な利用方法
- 最短のセットアップまたは実行方法
- 詳細な設計、API、運用文書への導線
- サポート範囲や重要な制約

### 避ける内容

- 全APIや全設定値の重複掲載
- 正規の設計文書と同期が必要な詳細説明
- 特定環境でしか成立しない値を一般的な既定値として扱う説明

## セットアップ手順

### 含める内容

- 対応OS、ランタイム、ツール、依存バージョン
- 必要な権限、アカウント、秘密情報の準備方法
- 実行ディレクトリと順序付きの手順
- 各段階の期待結果と最終確認方法
- ローカル、CI、本番など環境差がある場合の分岐
- 代表的な失敗の原因と確認先

### 完了条件

- 新しい環境から手順を順に実行できる。
- 文書へ含められない秘密情報や外部作業が明示されている。
- 初回実行後に正常性を確認できる。

## API文書

### 含める内容

- 目的、認証、認可、エンドポイントまたは操作
- 入力の型、必須項目、制約、既定値、例
- 出力の型、状態コード、エラー形式、例
- ページング、並び順、冪等性、レート制限
- バージョン、非推奨化、互換性、変更履歴への導線

### 正規の情報源

- OpenAPIなどから生成する場合は、スキーマまたは注釈を更新する。
- 生成されない設計理由や利用上の注意は、手書き文書へ分離する。
- 生成物への直接修正を避け、再生成手順を確認する。

## 設計文書

### 含める内容

- 解決する問題、対象範囲、非対象
- 現況、制約、維持する契約や不変条件
- 採用案、主要な代替案、判断理由
- 責務、データ、インターフェース、失敗時、運用
- 移行、ロールバック、テスト、未確定事項

### 区別する内容

- 現在の実装と将来案
- 確定事項と候補
- 要件と実装手段
- 一時的な互換処理と恒久設計

## 運用手順書

### 含める内容

- 開始条件、対象環境、必要権限、影響範囲
- 実行前の確認、順序付き操作、各段階の確認
- 停止条件、失敗時の復旧、ロールバック
- ログ、メトリクス、アラートの確認先
- エスカレーション条件と引き継ぐ情報

### 安全性

- 破壊的操作の対象を変数や曖昧なパターンへ依存させない。
- 本番と検証環境を誤認しない確認点を設ける。
- 認証情報や機微なログを文書へ貼り付けない。

## 移行ガイド

### 含める内容

- 対象バージョン、前提、破壊的変更
- 変更前後の対応関係と必要な作業
- データ、設定、API、依存関係の移行順序
- 互換期間、旧新混在、ロールバック条件
- 検証方法と移行完了後の撤去対象

### 完了条件

- 利用者が自分に必要な変更を特定できる。
- 省略時の既定動作や自動移行の範囲が明確である。
- 移行失敗時の復旧方法または制約が示されている。
