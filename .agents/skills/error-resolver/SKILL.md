# ビルドエラー解決

失敗したコマンドを再現し、最初の原因へ最小の修正を加え、同じ条件で解消を確認する。

## 適用範囲

- コンパイル、型検査、リンク、コード生成の失敗
- パッケージや依存関係の解決失敗
- ビルドツール、プラグイン、設定ファイルの不整合
- CIとローカル環境のビルド差異

アプリケーション実行後の挙動不良、性能最適化、一般的な環境構築はこのスキルの対象外とする。

## 参照

最初の有効なエラーを取得した後、修正前に[診断チェックリスト](references/diagnostic-checklist.md)の該当節を読む。元のコマンドを再実行した後、根本原因と再発条件を見落としていないか再確認する。エラーメッセージに現れない原因も、根拠がある場合に限って扱う。

## 進め方

1. 失敗した正確なコマンド、作業ディレクトリ、終了コード、最初の有効なエラーを取得する。
2. 言語、ランタイム、ビルドツール、ロックファイル、関連環境変数のバージョンと差異を確認する。
3. 後続エラーをいったん分離し、最初の失敗を構文・型・依存解決・生成・設定・資源・外部接続に分類する。
4. エラーが指すファイルに加えて、生成元、設定の継承元、依存グラフ、直前の関連変更を確認する。
5. 一つの仮説に対して最小の修正または診断コマンドを実行する。
6. 元と同じコマンドを再実行し、解消後に関連するテストやlintを確認する。
7. 修正内容、原因、検証結果、残る環境差異を報告する。

## 原因別の確認観点

### 構文、型、名前解決

- 最初の診断位置と、実際に構文や型が崩れ始めた位置
- 宣言、import、スコープ、型推論、オーバーロード、生成された型との整合
- ソースの問題か、生成物や古い解析結果の問題か

### 依存関係

- マニフェスト、ロックファイル、実際の解決結果の差
- 推移的依存、競合する複数バージョン、除外、プラットフォーム別成果物
- レジストリ、認証、プロキシ、証明書、ネットワークによる取得失敗
- ランタイム、コンパイラ、プラグイン、依存ライブラリ間の互換性

### 設定と生成

- 設定形式、キー名、階層、継承、環境別プロファイル
- 作業ディレクトリ、入力パス、出力パス、生成順序
- コード生成元と生成物の同期、必要なツールやプラグインの有無
- ローカルとCIで異なる既定値や条件分岐

### 環境と資源

- OS、アーキテクチャ、ツールチェーン、環境変数、ロケール、タイムゾーン
- ファイル権限、大文字小文字、パス長、ディスク、メモリ、ファイル記述子
- 並列実行時に限って生じる競合、共有ディレクトリ、ポート、テストデータの衝突
- 外部サービス障害と、ローカルの定義や実装に起因する失敗の切り分け

## 制約

- キャッシュ、ロックファイル、生成物を、原因の根拠なく削除しない。
- 依存関係の一括更新やツールチェーン変更を、局所的なエラーの回避策として行わない。
- 警告の抑制、型検査の無効化、検証ステップの削除で成功扱いにしない。
- ネットワーク、認証、レジストリ障害と、依存定義そのものの不整合を区別する。
- CIでのみ失敗する場合は、OS、アーキテクチャ、環境変数、権限、キャッシュキー、並列性の差を比較する。

## 出力

- 失敗したコマンドと主要エラー
- 根本原因と、それを示す根拠
- 実施した最小修正
- 再実行した検証と結果
- 未確認事項または再発条件
