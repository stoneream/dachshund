# プルリクエストレビューチェックリスト

PRまたはMRの比較範囲を確定した後に使用する。差分の各行だけでなく、変更意図、差分外の利用者、CI、導入時の挙動を確認する。

## 比較範囲

- 現在のブランチ、ベースブランチ、リモート追跡状態を確認する。
- `merge-base` が意図した分岐点か確認する。
- `base...HEAD`の差分と、左右にのみ存在するコミットを確認する。
- マージ、リベース、チェリーピックによって比較範囲から欠けた変更がないか確認する。
- 未コミット変更をPR差分と混同しない。

## 変更意図

- PRの説明、関連課題、コミット、実装から達成する結果を確認する。
- 説明にある変更が差分へ含まれ、差分にある変更が説明と矛盾しないか確認する。
- リファクタリング、挙動変更、設定変更、依存更新、生成物更新を分ける。
- 一時対応、互換処理、機能フラグに終了条件があるか確認する。
- コミットメッセージだけで意図を断定せず、patchと周辺実装で裏付ける。

## 差分の完全性

- 新しい型、API、設定、データ形式の呼び出し元と利用先が追従しているか確認する。
- 実装変更に対応するテスト、フィクスチャ、モック、スナップショットを確認する。
- README、API文書、設計書、運用手順への更新が必要か確認する。
- 生成元と生成物、マイグレーションとモデル、設定定義と環境別値が同期しているか確認する。
- 削除対象に参照、登録、文書、依存関係が残っていないか確認する。

## 挙動とデータ

- 正常系、境界値、異常系、再実行時の挙動が要件と一致するか確認する。
- 状態遷移、トランザクション、部分成功、重複処理を確認する。
- 既存データ、旧スキーマ、旧クライアントとの互換性を確認する。
- データ移行の順序、旧新バージョン混在、ロールバックを確認する。
- 時刻、順序、識別子、既定値、型変換による回帰を確認する。

## APIと設定

- 公開API、CLI、イベント、設定キー、環境変数の契約変更を確認する。
- 必須項目、既定値、省略時動作、列挙値、エラー形式の変化を確認する。
- 本番、ローカル、テスト、CIの設定が変更へ追従しているか確認する。
- 新しい秘密情報、権限、外部サービス、ネットワーク要件を確認する。
- 非推奨化、移行案内、互換期間が必要か確認する。

## 失敗時と運用

- エラー、タイムアウト、再試行、キャンセル、フォールバックを確認する。
- リソース解放、接続管理、ロック、並行実行を確認する。
- 障害と重要な状態変化を追跡するログ、メトリクス、トレースを確認する。
- デプロイ順序、機能フラグ、段階的導入、ロールバックを確認する。
- アラート、ダッシュボード、運用手順、問い合わせ対応への変更を確認する。

## セキュリティ

- 新しい入力境界、外部接続、権限、機微データの扱いを確認する。
- 認証、認可、所有権、テナント境界への影響を確認する。
- 重要な状態遷移が変わる場合、手順の省略、再送、競合による迂回を確認する。
- ログ、エラー、設定、フィクスチャへ秘密情報や個人情報が含まれていないか確認する。
- 依存関係や危険な機能の追加による攻撃面を確認する。
- CIが変わる場合、信頼できない入力を秘密情報や書き込み権限を持つ処理で実行していないか確認する。
- 専門的な分析が必要な変更を通常レビューだけで断定しない。

## コミット構成

- 各コミットが意図を説明でき、必要な追従変更を含んでいるか確認する。
- 後のコミットで修正された一時的な壊れ方を、最終差分の問題と混同しない。
- 取り込み漏れを疑う場合は、関連ブランチや過去コミットのpatchを比較する。
- コード移動と実質的な変更を分離して確認する。
- 生成物や大量整形が実質差分を隠していないか確認する。

## CIとテスト

- 必須CIが実行され、対象コミットに対する結果か確認する。
- 失敗、スキップ、許容失敗、再実行成功の理由を確認する。
- 変更の正常系、境界値、異常系、回帰条件をテストしているか確認する。
- 依存更新、設定変更、生成変更ではクリーンビルドを確認する。
- 必須テストやセキュリティ検査が削除、弱体化、条件分岐によって迂回されていないか確認する。
- 実行できない検証と残る不確実性を明記する。

## スコープとレビュー可能性

- PRの目的に無関係な変更が混在していないか確認する。
- 差分が大きい場合は、責務またはリスクごとに確認経路を分ける。
- 大量の機械変更でも、設定、生成元、例外箇所を確認する。
- 別PRへ分離すべき変更が、安全な導入順序を壊さないか確認する。

## 指摘化の条件

- ベース差分上の対象箇所を特定できる。
- 問題が成立する入力、状態、環境、導入順序を説明できる。
- 利用者、データ、運用、互換性へ与える影響を説明できる。
- CIや外部依存を確認できない場合は断定せず、未確認事項として分離する。
