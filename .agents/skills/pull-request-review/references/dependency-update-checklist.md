# 依存関係更新チェックリスト

直接依存、推移的依存、ビルドプラグイン、ランタイム、ロックファイルが変わる場合に使用する。公開日や既知の問題など変化しうる情報は、対象バージョンの公式一次情報で確認する。

依存関係の取得元、CI、SBOM、ビルドの生成記録、署名、成果物の配布までを横断して分析する場合は `software-supply-chain-analysis` を使用する。このチェックリストでは、更新差分の互換性と対象リポジトリ内の影響を主に確認する。

## 更新範囲

- 直接更新した依存と、解決結果として変わった推移的依存を分ける。
- マニフェスト、ロックファイル、依存グラフ、生成物の差を確認する。
- 開発、テスト、ビルド、本番など依存範囲の変化を確認する。
- ランタイム、コンパイラ、プラグイン、パッケージ管理ツールの組み合わせを確認する。
- 意図しないダウングレード、複数バージョン、除外解除を確認する。

## 一次情報

- 公式の変更履歴、リリースノート、移行ガイド、API文書を確認する。
- 対象の開始バージョンから終了バージョンまでの変更を確認する。
- 破壊的変更、非推奨化、削除、既定値変更、既知の問題を確認する。
- メジャーバージョンだけでなく、マイナー更新の挙動変更も確認する。
- 二次情報を利用する場合は、一次情報または実装で裏付ける。

## APIと実装追従

- 削除または変更されたAPIの利用箇所を検索する。
- 推奨される置換先が、旧実装と同じ契約を持つか確認する。
- 型、例外、戻り値、同期・非同期、ライフサイクルの変化を確認する。
- 初期化、ビルダー、ファクトリ、依存注入の変更を確認する。
- コンパイル成功だけでは検出できない実行時挙動を確認する。

## 既定値と設定

- タイムアウト、接続数、再試行、TLS、認証、キャッシュなどの既定値を確認する。
- 旧実装で明示していた値が、新実装で省略されていないか確認する。
- 設定キー、単位、優先順位、環境変数の変更を確認する。
- 本番、ローカル、テスト、CIで異なる設定経路を確認する。
- 既定値へ委ねる場合は、旧挙動と同等である根拠を確認する。

## 互換性

- 対応OS、アーキテクチャ、ランタイム、言語バージョンを確認する。
- プロトコル、データ形式、データベース、外部サービスとの互換性を確認する。
- プラグインや連携ライブラリが新しいバージョンへ対応しているか確認する。
- 旧新ノードやクライアントが混在する期間の挙動を確認する。
- ネイティブ成果物、ABI、動的リンクの変化を確認する。

## セキュリティと供給元

- 修正対象の脆弱性が実際の利用経路へ影響するか確認する。
- 更新で新しい権限、外部通信、スクリプト実行が追加されないか確認する。
- パッケージ名、配布元、署名、ハッシュ、レジストリを確認する。
- インストール時やビルド時に実行されるスクリプトと、追加される外部通信や権限を確認する。
- 保守状況、所有者変更、ライセンス変更が利用条件へ影響しないか確認する。
- 自動更新を抑止していた場合は、過去の回帰理由を履歴から確認する。

## ロックファイルと再現性

- 正規のパッケージ管理コマンドでロックファイルを更新しているか確認する。
- 無関係な依存の大規模更新が混在していないか確認する。
- クリーン環境で同じ解決結果と成果物を再現できるか確認する。
- キャッシュが古い成果物や異なるプラットフォーム成果物を隠していないか確認する。
- 同梱、チェックサム、ミラー、プロキシの更新を確認する。

## 検証

- 依存解決とクリーンビルドが成功する。
- 型検査、単体、統合、E2Eのうち変更へ関係する検証が成功する。
- 初期化、設定読み込み、接続、代表的な実行経路を確認する。
- 性能や資源既定値が変わる場合は、該当する負荷または計測を確認する。
- ロールバック時にロックファイル、データ、設定を戻せるか確認する。

## 指摘化の条件

- 対象バージョン間の具体的な変更を一次情報で示せる。
- リポジトリ内の利用箇所または設定へ影響する経路を示せる。
- 互換性や既定値の不確実性を、既知の問題として断定していない。
- 更新しないリスクと更新するリスクを区別している。
