# ソース管理・ビルド・配布

ソース管理、CI、依存関係の取得、SBOM、ビルド、成果物、デプロイを変更する場合に使用する。ソースから稼働中の成果物まで、入力、処理を実行するアクター、権限、生成物を追跡できる経路を作る。

## ソース管理と変更の承認

- 保護ブランチ、必須検査、レビュー、マージ、タグ、リリースの実効設定を変更内容とともに管理する。
- 一人または一つの自動処理が、重要な変更の作成、承認、配布を単独で完了できないように権限を分ける。
- ボット、サービスアカウント、連携機能、デプロイ鍵の権限と有効期間を用途へ限定する。
- サブモジュール、生成ソース、同梱コード、ワークフロー、ツール向け指示も、ビルド結果へ影響する変更として扱う。
- 廃止したブランチ、タグ、クレデンシャル、連携機能、成果物の参照を残さない。

## CIの起動条件と入力

- プルリクエスト、フォーク、課題、コメント、手動引数、Webhookなど、ワークフローを起動できる入力を列挙する。
- 未検証のコードを、秘密情報または書き込み権限を持つジョブで実行しない。
- ブランチ名、コミットメッセージ、課題本文、成果物名などをシェルへ直接展開しない。
- 特権ジョブでは、承認済みのリビジョン、ワークフロー定義、引数、成果物を固定して使用する。
- 外部提供のCIアクション、共有ワークフロー、プラグイン、ビルドイメージは、変更できない識別子へ固定し、更新差分を確認する。
- 必須テストやセキュリティ検査を、条件分岐、失敗許容、別の起動経路から迂回できない構成にする。

## ランナーとクレデンシャル

- 未検証の変更を、内部ネットワークへ到達できる自己管理ランナーで実行しない。
- ジョブごとに初期化した環境を使用し、作業領域、プロセス、キャッシュ、クレデンシャルを別のジョブへ残さない。
- トークンをジョブ、手順、環境、対象資源へ限定し、有効期間の短いクレデンシャルを使用する。
- 秘密情報をコマンド引数、環境出力、ログ、キャッシュ、成果物、テスト報告へ流さない。
- ランナーから内部サービス、メタデータ、成果物保管庫、外部ネットワークへの到達範囲を限定する。

## 依存関係、SBOM、ビルド

- 依存関係の取得元、レジストリの優先順位、ミラー、プロキシ、チェックサムを固定する。
- SBOMはマニフェストだけでなく、ビルド時に解決した依存関係と最終成果物からリリースごとに生成する。
- ソースのリビジョン、依存関係、ビルド定義、ランナー、ツールチェーン、引数、成果物のダイジェストを生成記録へ残す。
- ビルドツール、プラグイン、ベースイメージをレビュー済みの版へ固定し、初期化した分離環境でビルドする。
- 成果物から試験用の鍵、開発用接続先、不要なデバッグ情報を除外する。
- 成果物、SBOM、生成記録、署名を同じリリースとダイジェストへ結び付ける。

## 成果物とデプロイ

- 成果物は上書きできないバージョンとダイジェストで保管し、アップロード、承認、削除、タグ変更の権限を分ける。
- デプロイ前に、成果物のダイジェスト、生成記録、署名、承認対象の環境を検証する。
- ビルドジョブへ恒久的な本番権限を与えず、デプロイを実行するアクターを環境と操作へ限定する。
- 構成、マイグレーション、秘密情報、インフラ変更を、配布する成果物との組み合わせで追跡する。
- 侵害時にトークン失効、ランナー隔離、リリース停止、成果物撤回、既知の安全な版への復旧を実行できるようにする。
- 稼働中のバージョンと成果物のダイジェストを把握し、新しい脆弱性や撤回対象と照合できるようにする。

## 検証

- フォークや未検証の入力から、秘密情報、書き込み権限、内部ランナー、本番環境へ到達できないことを確認する。
- 初期化した環境で同じ入力から意図した成果物を生成し、生成記録とSBOMを対応付ける。
- 未承認または改ざんされた成果物が、本番向け承認やデプロイで拒否されることを確認する。
- 必須検査の失敗、外部サービスの停止、クレデンシャル失効時に、安全でない成果物を配布しないことを確認する。
