# アプリケーション境界

外部入力、出力、ファイル、外部接続、API、ブラウザ、クライアントを変更する場合に使用する。境界へ到達するデータと、防御を強制する場所を先に特定する。

## 入力と出力

- HTTP、API、ファイル、メッセージ、Webhook、外部サービスの応答、管理画面から入る値を信頼できない入力として扱う。
- 型、形式、長さ、件数、範囲、文字集合に加え、現在の権限と業務状態に照らして値を検証する。
- 正規化や型変換は検証前後の順序を固定し、検証後に別の表現へ変換して制約を失わないようにする。
- SQL、シェル、LDAP、テンプレートなどの命令と値を、対象のAPIが提供する仕組みで分離する。
- HTML、JavaScript、URL、CSS、HTTPヘッダーなど、出力先の文脈に合うエンコードまたは安全なAPIを使用する。
- 入力の不正を詳細な内部情報とともに返さず、調査に必要な情報は保護されたログへ記録する。

## リクエストと外部接続

- 状態変更リクエストでは、利用する認証方式に応じてオリジン、CSRF対策、再認証の要否を決める。
- 外部接続先を利用者が指定できる場合は、許可するスキーム、ホスト、ポート、解決後のアドレス、リダイレクト先を制限する。
- 接続処理へタイムアウト、応答サイズ、再試行回数、同時実行数の上限を設ける。
- 内部ネットワーク、メタデータサービス、管理面、ローカルファイルへ到達できない境界をアプリケーションと実行環境の両方に設ける。
- Webhookなど外部から届く通知は、送信元、署名、対象、時刻、再送を検証し、重複処理を防ぐ。
- リダイレクト先は許可した範囲から選び、文字列の前方一致だけで判定しない。

## ファイル

- ファイル名を保存先のパスとして直接使用せず、アプリケーション側で識別子と保存場所を決める。
- 種類、内容、サイズ、件数を検証し、拡張子や申告されたメディアタイプだけを信頼しない。
- 受領、検査、変換、保存、配信の各段階で、未検査のファイルを公開領域へ置かない。
- アーカイブ展開では、展開後のパスと総容量を制限し、既存ファイルの上書きを防ぐ。
- 画像変換、文書解析、ウイルス検査は、必要最小限の権限と資源上限を持つ分離した処理で実行する。
- ダウンロード時は認可を行い、内容に合うメディアタイプとダウンロード用ヘッダーを設定する。

## APIとサービス

- 認証だけでなく、操作、対象オブジェクト、プロパティ、テナント、状態ごとにサーバー側で認可する。
- 一括更新や自動バインドでは、利用者が変更できる項目を明示し、所有者や権限などの保護項目を除外する。
- 一覧、検索、エクスポートでは、認可済みの範囲へ絞り、件数、ページング、返却項目へ上限を設ける。
- GraphQLのリゾルバー、WebSocketのメッセージ、gRPCのメソッド、非同期処理にも同じ認可とテナント境界を適用する。
- ストリーム、購読、長時間接続では、権限変更、ログアウト、クレデンシャル失効を既存接続へ反映する。
- 内部サービス間でも相手と委任範囲を検証し、ネットワーク上の位置だけを信頼しない。

## ブラウザとクライアント

- DOMへ挿入する値は安全なAPIで扱い、HTMLやスクリプトとして解釈するAPIの使用箇所を限定する。
- `postMessage`、ディープリンク、URLスキーム、拡張機能のメッセージでは、送信元、対象、形式、操作権限を検証する。
- トークンや機微データをURL、ブラウザの不要な保存領域、クライアントログへ残さない。
- 外部サービスから読み込むスクリプトは必要なものに限定し、コンテンツセキュリティポリシー、完全性検証、別オリジンやサンドボックスによる分離を検討する。
- クライアント内の非表示、難読化、改変検知を、サーバー側の認可やデータ検証の代わりにしない。
- ブラウザ拡張やモバイルアプリの権限は、利用するAPI、ホスト、ファイル、端末機能へ限定する。

## 検証

- 正常な入力に加え、不正な型、境界値、過大な入力、別の表現へ正規化される入力を試す。
- 別の利用者、ロール、テナント、オブジェクト、通信形式から同じ操作へ到達する経路を試す。
- 外部サービスの失敗、遅延、過大な応答、リダイレクト、再送時にも保護が維持されることを確認する。
- ブラウザやクライアントを改変しても、保護対象の判断を迂回できないことを確認する。
