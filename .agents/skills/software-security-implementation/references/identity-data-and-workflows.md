# 認証認可・データ・業務フロー

認証、認可、セッション、テナント分離、秘密情報、機微データ、重要な状態遷移を変更する場合に使用する。アクター、操作、対象、状態を組み合わせて、許可する条件と拒否する条件を定義する。

## 認証とアカウント

- 認証処理は、実績のあるライブラリや外部認証基盤の検証機能を使用し、トークンや署名を独自に解釈しない。
- パスワードは対象環境で支持される方式と設定でハッシュ化し、平文や復号可能な形式で保持しない。
- ログイン、回復、登録、メールアドレス変更、多要素認証の追加と解除を、同じ強度の本人確認で保護する。
- 認証失敗の応答からアカウントの存在や内部の判定理由を過度に露出しない。
- 試行回数や通知を、通常利用とサービス妨害への耐性を保てる単位で制御する。
- 送金、クレデンシャル変更、権限変更などの重要操作には、操作内容へ結び付いた再認証または確認と、有効期限、単回利用を組み込む。

## セッションとクレデンシャル

- セッション識別子とトークンは十分な強度で生成し、URL、ログ、リファラーへ含めない。
- Cookieは用途に応じて `Secure`、`HttpOnly`、`SameSite`、ドメイン、パス、有効期限を限定する。
- ログイン、権限変更、パスワード変更、回復、ログアウト時に、影響するセッションとトークンを更新または失効する。
- アクセストークン、更新トークン、APIキーを用途と対象サービスへ限定し、必要以上に長い有効期間を与えない。
- 失効、鍵のローテーション、端末の紛失、複数端末利用時の挙動を実装とテストへ含める。

## 認可とテナント分離

- 明示的に許可した操作だけを通し、認可処理が失敗した場合も拒否する。
- アクター、ロール、操作、対象オブジェクト、テナント、状態を軸に認可規則を定義する。
- UIの表示制御とは別に、サーバー側の各操作で認可する。
- テナントや所有者は認証済みの文脈から導出し、利用者が送る識別子だけで決めない。
- データベース条件、検索、キャッシュ、ファイル、キュー、ジョブにもテナント境界を含める。
- 管理者、サポート担当者、代理操作には、対象、理由、有効期間、監査記録を結び付ける。
- バッチ、エクスポート、バックグラウンド処理、管理APIへ通常経路と同じ認可規則を適用する。

## データと秘密情報

- 収集、保存、転送、共有、ログ記録、削除の各段階で必要なデータだけを扱う。
- API応答、エラー、ログ、監視、分析データ、テスト用データから秘密情報と不要な機微データを除外する。
- 秘密情報は専用の保管機構から実行時に取得し、ソース、通常の設定、コンテナイメージ、成果物へ埋め込まない。
- クレデンシャルと暗号鍵の発行、利用範囲、ローテーション、失効、監査を定義する。
- 転送時と保存時の保護には、対象環境で支持される方式とライブラリを使用し、独自の暗号方式を作らない。
- 暗号化を認可、完全性、削除要件の代わりにしない。
- 保持期限と削除処理を、複製、キャッシュ、検索インデックス、バックアップまで含めて設計する。

## 業務フローと状態遷移

- 許可する状態遷移と、その遷移を実行できるロールをサーバー側で定義する。
- 手順の省略、順序変更、取消後の再実行、期限切れ、重複要求を拒否または安全に処理する。
- 価格、割引、手数料、所有者、権限、承認状態などの判断値は、信頼できるデータからサーバー側で導出する。
- 在庫、残高、利用上限、クーポン、承認などは、競合や再試行でも不変条件を破らない単位で更新する。
- 外部決済や非同期処理では、冪等性キー、対象、金額、状態、有効期限を結び付け、応答の再送と順序入れ替わりを扱う。
- 途中失敗や補償処理で、二重付与、二重請求、未認可の確定状態を残さない。
- 資源を消費する処理には、アクター、テナント、対象資源に合う回数、件数、同時実行数の上限を設ける。

## 検証

- 未認証、期限切れ、失効済み、別用途のクレデンシャルで拒否されることを確認する。
- ロール、テナント、所有者、オブジェクト、状態を一つずつ変え、許可されない組み合わせを試す。
- 手順の省略、順序変更、再送、同時実行、途中失敗を再現し、安全な状態へ収束することを確認する。
- 応答、ログ、監査記録、テスト結果へ秘密情報や不要な機微データが残らないことを確認する。
