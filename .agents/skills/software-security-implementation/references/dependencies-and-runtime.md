# 依存関係と実行時

ライブラリ、フレームワーク、プラグイン、コード生成、デシリアライズ、動的実行、実行時設定を変更する場合に使用する。依存関係の追加や更新は、取得時、ビルド時、実行時に増える処理と権限まで確認して実装する。

## 依存関係

- 既存機能や標準ライブラリで満たせない要件を明確にしてから依存関係を追加する。
- パッケージ名、提供元、レジストリ、バージョン、チェックサム、ライセンス、保守状況を確認する。
- ロックファイルを更新し、意図した直接依存と推移的依存だけが変わるようにする。
- インストール時やビルド時に実行されるスクリプト、外部バイナリ、コード生成が使う権限と外部通信を把握する。
- 必要な機能だけを有効にし、未使用の依存関係、プラグイン、オプションを削除する。
- 既知の脆弱性は対象バージョンと利用経路を確認し、更新、機能停止、期限付きの緩和策から実行可能な対応を選ぶ。

## フレームワークと実行時設定

- 本番環境では、開発サーバー、詳細エラー、デバッグ機能、試験用認証、不要な管理機能を無効にする。
- 信頼するプロキシ、ホスト、オリジン、Cookie、セッション、外部接続先を明示する。
- フレームワークの認証認可、入力検証、出力処理、CSRF対策などの安全機能を共通経路で有効にする。
- 共通経路が適用されないルート、独自実装、旧版API、例外設定を減らす。
- 設定値の既定値を安全側に置き、値の欠落や読み込み失敗を保護機能の無効化として扱わない。
- 管理画面、診断、メトリクス、正常性確認の公開範囲と認証を用途に合わせて限定する。

## デシリアライズと動的実行

- 信頼できない入力から任意の型、クラス、関数、テンプレート、プラグインを選択できない形式を使う。
- デシリアライズする型と項目を明示し、コンストラクタ、フック、ゲッターなどの副作用を実行させない。
- `eval`、シェル、式評価、テンプレート実行を避け、必要な操作を型付きのAPIや許可済みの選択肢へ置き換える。
- 外部コマンドが必要な場合はシェルを介さず、実行ファイルと引数を分離し、許可する操作を限定する。
- 署名や暗号化だけを、信頼できない送信者の入力を安全と扱う根拠にしない。

## 権限と資源

- プロセス、コンテナ、プラグイン、変換処理には、必要なファイル、ネットワーク、データベース、秘密情報だけを許可する。
- 子プロセスや外部ツールへ、親プロセスのクレデンシャルと環境変数を無条件に引き継がない。
- 入力サイズ、ネスト、処理時間、メモリ、同時実行数、再試行回数へ上限を設ける。
- 一つの処理の失敗や侵害が、別のテナント、管理面、ビルド環境へ広がらない境界を設ける。
- 一時ファイル、作業ディレクトリ、キャッシュは権限を限定し、処理後に秘密情報を残さない。

## エラーと観測

- 利用者向けエラーから、スタックトレース、内部パス、環境変数、依存バージョン、接続情報を除外する。
- 調査用ログには操作と相関情報を残し、クレデンシャルや機微データを記録しない。
- 防御機能の失敗を通常処理の成功として扱わず、安全な状態で停止して観測できるようにする。
- 診断ダンプ、クラッシュレポート、プロファイラーの保存先、閲覧権限、保持期間を限定する。

## 検証

- クリーン環境で依存関係を解決し、ロックファイルと成果物が意図した内容になることを確認する。
- 開発用設定や環境変数を除いた本番相当の設定で、保護機能が有効になることを確認する。
- 不正な形式、未許可の型、過大な入力、処理失敗時に、動的実行や過剰な資源消費へ進まないことを確認する。
- 依存関係や外部ツールの失敗時にも、秘密情報の露出や保護機能の迂回が起きないことを確認する。
