title: ジョブ
---

## 概要

daemon のジョブは、定期的に実行されるバックグラウンド処理である。

ジョブごとの処理内容は個別のドキュメントに記載する。
このドキュメントでは、ジョブ全体に共通する実行方式と設定値について記載する。

## 実行方式

daemon 起動時に、登録されているジョブは並列に起動される。
各ジョブは起動後すぐに初回実行され、その後はそのジョブに設定されている次回実行までの待ち時間に従って実行される。

実行中のジョブで設定されているタイムアウトが経過した場合、その試行は失敗として扱われる。
失敗した試行は `retry` 設定に従って再試行され、初回実行を含む最大試行回数に達した場合はその回のジョブ実行を終了する。
その回のジョブ実行が失敗した場合でも、ジョブ自体は停止せず、次回実行までの待ち時間のあと再び実行される。

ジョブ同士の実行順序は管理していない。
ジョブ間の連携は、実行順ではなく DB 上のキューや同期済みデータの状態によって表現する。

たとえば、後続ジョブが先に実行された場合でも、処理対象のデータが存在しなければ何もせず終了する。
その後、前段のジョブがデータを作成すると、後続ジョブは次回実行時にそのデータを処理する。

そのため、ジョブに時間的な優先順位を持たせる必要はない。

## 設定値

| 設定値 | 説明 |
| --- | --- |
| `interval` | 通常の次回実行までの待ち時間。初回実行は `interval` を待たずに行われる。 |
| `timeout` | 1 回の実行試行に対するタイムアウト。 |
| `retry.max-attempts` | 初回実行を含めた最大試行回数。たとえば `3` の場合、初回実行とリトライ 2 回まで試行する。 |
| `retry.base-delay` | 最初のリトライ待ち時間。以後のリトライではこの値を基準に待ち時間が増える。 |
| `retry.max-delay` | リトライ待ち時間が増えた場合の上限値。 |
| `retry.jitter-ratio` | リトライ待ち時間に揺らぎを加えるための値。 |

## 補足

`interval` と `retry` の待ち時間は用途が異なる。
`interval` は通常の次回実行までの待ち時間であり、`retry` の待ち時間は失敗した同じ実行回を再試行するまでの待ち時間である。

失敗時に次回の `interval` まで待たずに再試行するのは、一時的な失敗を短時間で回復できるようにするためである。
ただし、失敗直後に即時再試行すると、外部 API や DB に連続して負荷をかける可能性があるため、リトライ待ち時間を設定している。

`retry.jitter-ratio` は、複数のジョブやプロセスが同じタイミングで再試行することを避けるために設定する。
待ち時間に揺らぎを加えることで、再試行の集中を分散する。

同じ `retry` 設定が複数のジョブに記載されているが、現状は共通デフォルトを継承しているわけではない。
各ジョブの設定として明示的に同じ値を記載している。
