---
title: 監査ユーザー規約
---

## 目的

DB の `created_user`、`updated_user`、`deleted_user` に保存する値の規約を定義する。

## 保存形式

アプリケーションコードでは監査主体を Scala の `AuditUser` enum で表現し、DB 書き込み時は `dbValue` を保存する。

```scala
enum AuditUser {
  case System
  case User(userId: Long)
}
```

保存値は次の通り。

| 監査主体 | DB 保存値 |
| --- | --- |
| `AuditUser.System` | `system` |
| `AuditUser.User(123)` | `user:123` |

enum の `toString` には依存せず、必ず `dbValue` を使う。

## 適用方針

ユーザー ID が確定している処理では `AuditUser.User(userId)` を使う。
たとえば、ユーザー作成後のユーザー行、外部認証成功後の認可情報、セッション発行、登録完了では `user:<id>` を保存する。

ユーザー ID が未確定の処理、または daemon / job の自動処理では `AuditUser.System` を使う。
たとえば、外部認証リクエストの作成、コールバック処理開始、ユーザー未確定の失敗確定、トークン更新ジョブの状態更新では `system` を保存する。

自動採番のユーザー行は insert 後にユーザー ID が確定する。
そのため、同一トランザクション内で `created_user` と `updated_user` を `user:<id>` に補正する。
この補正は監査主体の確定処理なので、`updated_at` と `lock_version` は更新しない。

## deleted_user

未削除行の `deleted_user` は空文字列を保存する。
これは未削除状態を表す値であり、`AuditUser` の一種としては扱わない。
