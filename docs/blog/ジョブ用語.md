## 目的

この文書は、daemon ジョブとキューテーブルで共通して使う用語をまとめる。
個別ジョブの仕様では、ここで定義した状態名、再試行、ロックの語彙を使う。

## 表記方針

DB テーブル名、カラム名、状態値などの識別子はそのまま記載する。
説明文では、`queue` はキュー、`retry` は再試行、`lock` はロック、`lease` はロック期限またはロック期限管理と書く。

## daemon 起動時の実行

daemon 起動時は、読み込まれた各ジョブを一度ずつ即時実行する。
初回実行にもタイムアウトと再試行設定を適用する。
初回実行後は、各ジョブのスケジュールに従って次回実行まで待機する。

## キュー状態

キューテーブルの実行状態は共通カラム名 `status` で管理する。
状態は `SCHEDULED`、`PROCESSING`、`SUCCEEDED`、`FAILED`、`BLOCKED`、`SKIPPED` を共通語彙にする。

| 状態 | 日本語名 | 意味 |
| ---- | -------- | ---- |
| `SCHEDULED` | 実行待ち | `next_attempt_at` 以降に処理対象として取得される。 |
| `PROCESSING` | 処理中 | ワーカーが処理対象として取得済みで、`lock_token` と `locked_until` によりロック期限で管理されている。 |
| `SUCCEEDED` | 完了 | 対象キューの処理が正常に完了している。 |
| `FAILED` | 失敗 | 失敗として記録された状態。個別ジョブでは再スケジュール対象として扱う場合がある。 |
| `BLOCKED` | 要対応 | ユーザー操作または運用対応が必要で、通常の再試行対象から外れている。 |
| `SKIPPED` | スキップ済み | 処理対象外などにより、実行しないことが確定している。 |

## 再試行とロック

再試行と実行管理には、キューテーブルの共通カラムを使う。

| カラム | 意味 |
| ------ | ---- |
| `next_attempt_at` | 次に実行対象へ戻す日時。 |
| `attempt_count` | 試行回数。処理対象として取得した時、またはジョブ固有の再試行管理で更新する。 |
| `last_attempted_at` | 最後に実行を試みた日時。 |
| `completed_at` | 正常完了した日時。 |
| `last_failed_at` | 最後に失敗した日時。 |
| `last_error_type` | 最後に記録したエラー種別。 |
| `lock_token` | 処理対象として取得したワーカーを識別するトークン。 |
| `locked_until` | 処理対象として取得した状態のロック期限。期限切れの `PROCESSING` のキューは再取得可能な状態へ戻す。 |
